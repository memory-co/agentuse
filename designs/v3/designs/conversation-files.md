# Conversation 文件树与消息附件

每个 conversation 是一个独立文件命名空间。attachments.relative_path 保存规范化的相对文件路径，(session_id, relative_path) 唯一；实际字节内容仍按附件 ID 保存。文件树从路径派生，不读取或暴露 Server/Client 的主机目录。

## 路径

- 用户上传进入保留目录 user_input/，支持目录层级。
- AI 上传保留 workspace 内的相对路径；外部文件使用 basename。
- AI 不能写入 user_input/。
- 路径不接受绝对地址、反斜线、空目录段、`.`、`..` 或控制字符。
- 同路径上传在同一发布事务内分配编号路径，不覆盖旧内容；文件与目录不能占用同一位置。
- conversation 之间不共享路径或目录状态。

## 消息关联

HTTP message 请求显式携带 attachment_ids；省略表示空，不继承整个 conversation 的文件。Server 在提交消息的同一事务内校验归属，并把附件元数据快照存入 messages.attachments。

Server 首次投递该消息时直接使用已保存快照。随后上传到文件树但未被消息选择的文件不会出现在 Client 输入中。多个 Agent 接收同一消息时使用同一份附件集合；多个输入归属同一 run 时，由 Client 合并已受理输入的快照。

最终 result 事务在写入 AI 回复时，关联该 run 已上传的输出文件。不额外创建 task 或文件交付实体。输入和输出的卡片都可以打开右侧预览。

已被消息引用的附件不单独删除，避免历史引用和待执行输入失效；未引用的上传可以删除。删除整个 conversation 沿用既有文件清理流程。

## 页面

对话区域与文件树是并排的独立滚动区域。小屏幕使用文件抽屉。输入框提供上传按钮、待发送文件卡片和上传进度，成功发送后清空选择；失败时保留已上传文件的 ID，重试不重复上传。

右侧按相对路径显示目录树，支持搜索、图片/文本预览、下载及添加到消息。附件元数据请求和预览沿用用户/管理员代为身份，使用同一个权限范围。

## 存储与版本

schema 6 为 attachments 增加 relative_path，为 messages 增加 attachments JSON 快照。无旧数据迁移、旧字段别名或整会话附件回退。HTTP /api/sessions 和既有附件内容下载地址不变。
