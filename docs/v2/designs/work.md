# 工作(work)

工作 = 一组会话，照 Claude Projects 的样子：一个工作有名字和一份**说明**(instructions),放进这个工作的会话都带着这份说明跑。适合「同一件事开好几个会话」:比如「重构 daemon」下面开几个会话分别改代码、写测试、写文档，说明里写清背景和约定，不用每个会话都重复交代。

表见 [tables/works](../tables/works.md),接口见 [apis/works](../apis/works.md)。

## 规则

- **一个会话最多属于一个工作**:`sessions.work_id`,可以为空(不属于任何工作，和现在一样)。
- **工作是个人的**:属于建它的用户，只有主人(和 admin)能看、改、删、往里放会话。
- **谁能放**:会话的发起人(`created_by`)才能把会话放进 / 移出自己的工作。用别人的 agent 开的会话也能放进自己的工作;agent 的主人照样能看到这个会话，但看不到这个工作。
- **不绑 agent**:同一个工作里的会话可以用不同的 agent、跑在不同的 daemon 上。工作只管「分组 + 说明」。
- **移动**:会话随时可以移进、移出、换工作，只影响之后的消息带哪份说明，已经跑过的不变。
- **删除工作**:只删工作本身，里面的会话保留，`work_id` 变空，回到不属于任何工作。
- **文件(知识库)**:Claude Projects 还能挂文件，先不做，以后再加。

## 说明怎么交给 harness

派活时服务把会话所在工作的 `instructions` 放进 daemon 收到的 `message` 里([apis/daemon](../apis/daemon.md)),没有就不带。daemon 每次起进程前在会话目录里按 harness 写好:

| harness | 写到哪 |
|---|---|
| `claude` | `~/.agentuse/work/<session_id>/CLAUDE.md` |
| `codex` | `~/.agentuse/work/<session_id>/AGENTS.md` |
| 自定义 | 不写文件,stdin 里多一个 `"instructions": "…"` 字段 |

- 写哪个文件放在 `harness/<name>/harness.yaml` 的 `instructions: CLAUDE.md` 一项里([harness](harness.md))。
- **每条消息都重写**:说明改了、会话换了工作，下一条消息就用新的;没有说明就把这个文件删掉。这个文件归 agentuse 管，harness 在会话里自己改了也会被覆盖。
- 续接的会话(`--resume`)也会重新读到目录里的 CLAUDE.md,所以改说明对已有会话的下一条消息生效。

## 网页

侧边栏原来的会话列表上方加两个 tab:**会话** / **工作**(英文 Sessions / Works),选中哪个记在 localStorage。

- **会话** tab:和现在一样，列出全部会话(包括在工作里的);在工作里的会话标题下面灰字显示工作名。
- **工作** tab:列出我的工作，按 `updated_at` 新的在前。顶部一个「+ 新建工作」;一个都没有时显示虚线框空状态(「把相关的会话放在一起，共用一份说明」+「新建工作」按钮)。点一个工作进 `/works/:id`。
- **工作页**(右侧主区):
  - 标题：工作名，点一下就能改。
  - 新建会话框：和首页一样选 agent、写 prompt,开出来的会话直接属于这个工作。
  - 「说明」卡片：多行文本框 + 保存，提示「这个工作里的每个会话都会带上」。
  - 下面列出这个工作的会话，点进会话页。
  - 右上角菜单：删除工作(确认框里说明会话会保留)。
- **会话页**:顶部标题前面显示所属工作名(点了回工作页);标题旁菜单里加「移到工作…」,弹出选择(含「不属于任何工作」)。只有发起人看得到这一项。
- **新建工作**:弹框填名字(必填)和说明(可空),建好进工作页。
- 手机：同样的 tab 放在侧边栏那一屏里。
